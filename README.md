## سؤال اول: تفاوت نسخه‌های HTTP

### تفاوت نسخه‌ها

<p dir="rtl" align="right">• <code>HTTP/0.9</code>: اولین و ساده‌ترین نسخه HTTP بود. فقط از متد <code>GET</code> پشتیبانی می‌کرد و Header و Status Code نداشت.</p>

<p dir="rtl" align="right">• <code>HTTP/1.0</code>: قابلیت‌هایی مثل Header و Status Code به آن اضافه شدند. معمولا برای دریافت هر منبع، یک اتصال TCP جداگانه برقرار می‌شد.</p>

<p dir="rtl" align="right">• <code>HTTP/1.1</code>: امکان استفاده مجدد از اتصال TCP با <code>Persistent Connection</code> و ارسال چند درخواست پشت سر هم با <code>Pipelining</code> فراهم شد.</p>

<p dir="rtl" align="right">• <code>HTTP/2</code>: با استفاده از <code>Multiplexing</code> می‌توان چند درخواست و پاسخ را به صورت همزمان روی یک اتصال TCP ارسال کرد.</p>

<p dir="rtl" align="right">• <code>HTTP/3</code>: به جای TCP از پروتکل QUIC بر پایه UDP استفاده می‌کند. این نسخه مشکل مسدود شدن جریان‌های دیگر هنگام گم شدن یک بسته را کاهش می‌دهد.</p>

### چرا HTTP/3 از UDP استفاده می‌کند؟

در HTTP/2 با اینکه چند درخواست می‌توانند همزمان ارسال شوند، همه آن‌ها از یک اتصال TCP استفاده می‌کنند. به همین دلیل اگر بسته‌ای گم شود، ممکن است بقیه درخواست‌ها هم تا دریافت دوباره آن بسته منتظر بمانند. به این مشکل `Head-of-Line Blocking` گفته می‌شود.

در HTTP/3 از پروتکل QUIC روی UDP استفاده شده تا جریان‌های داده مستقل‌تر باشند و گم شدن بسته مربوط به یک جریان باعث توقف بقیه جریان‌ها نشود. همچنین QUIC امکان برقراری سریع‌تر اتصال را فراهم می‌کند.

## سؤال دوم

**الف)**

در ارتباطات **Stateful**، سرور وضعیت و اطلاعات مربوط به درخواست‌های قبلی کاربر را نگه می‌دارد و می‌تواند در درخواست‌های بعدی از آن‌ها استفاده کند. اما در ارتباطات **Stateless**، هر درخواست مستقل از درخواست‌های قبلی پردازش می‌شود و سرور به صورت پیش‌فرض اطلاعاتی از وضعیت قبلی کاربر نگه نمی‌دارد.

**ب)**

پروتکل HTTP از نوع **Stateless** است؛ یعنی سرور به صورت پیش‌فرض وضعیت درخواست‌های قبلی کاربر را به خاطر نمی‌سپارد. این موضوع برای کارهایی مثل حفظ وضعیت ورود کاربران مشکل ایجاد می‌کند.

برای حل این مشکل می‌توان از **Cookie** و **Session** استفاده کرد. سرور با هدر `Set-Cookie` یک شناسه به مرورگر می‌فرستد و مرورگر در درخواست‌های بعدی آن را با هدر `Cookie` برمی‌گرداند. به این ترتیب سرور می‌تواند اطلاعات مربوط به Session کاربر را پیدا کند. روش دیگر استفاده از توکن‌هایی مثل `JWT` است که همراه درخواست ارسال می‌شوند و به شناسایی کاربر کمک می‌کنند.
